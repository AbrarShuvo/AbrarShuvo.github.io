The problem

The decisions were in the recording. Nobody had time to find them.

A design agency records its client meetings. One designer watches the whole recording, writes down what the client asked for, and carries it to the team. It works, but it costs a full rewatch every time, and anything missed on that pass is simply lost.

Before
Someone rewatches the full recording
Notes live in one person's head
No record of who owns what
After
One command, structured output
Every task has an owner and a date
Decisions kept separately, on the record
How it works

Three steps, one command

1

Read the transcript

The reader takes the raw transcript file, cleans it up and splits it into speaker turns with timestamps.

2

Extract with AI

The model is asked for one exact shape of answer, not free text: tasks, owners, dates and decisions, each in its own field.

3

Check and save

Every answer is validated against the schema, retried if it comes back malformed, then written out as tasks.json.

transcript.txt AI extraction schema check tasks.json
Decisions I made

Making an AI tool you can actually trust

An AI tool is only useful if its output is predictable. Most of the work went into making the result the same shape every single time.

A fixed output shape

The model has to answer inside a schema, so the result can be read by other software instead of a human.

Retries on bad answers

If a reply doesn't fit the schema, it's asked again rather than passed on broken.

Answer keys written first

I wrote what the correct output should be before running the tool, so the tests measure accuracy and not just "it ran".

It gets every task right, on every test I've written.
